# TSPICE Laboratory

Настольное приложение на Python/PyQt6 для анализа характеристик кастомных транзисторов, оценки параметров компактной модели и экспорта карты SPICE.

## Что реализовано

- Переключаемые формы параметров для planar MOSFET, FD-SOI, FinFET, GAA nanosheet, GAA nanowire, TFET, HEMT, мемристора и мемтранзистора.
- Импорт табличных CSV/Silvaco `.log` (разделители CSV или пробелы) и расчёт метрик Id–Vg, Id–Vd, Ig–Vg, C–V, Gummel, BJT output, AC, transient и gate-charge кривых.
- Объектно-ориентированный backend экстракции выбирается по типу структуры из интерфейса: LEVEL=54 для bulk/приближённого FD-SOI, LEVEL=72 для FinFET/GAA, поведенческие `.subckt` для TFET/HEMT/CAD. Экспорт модели доступен через **Экспорт компактной модели**.
- Выпадающий селектор над графиком показывает все типы кривых, найденные в загруженных файлах; одинаковые характеристики из нескольких наборов накладываются на один график. Встроенные образцы загружаются кнопкой **Загрузить примеры**, а метрики всех файлов — кнопкой **Рассчитать все кривые**.
- Кнопка **Получить характеристики (PDE)** добавляет рассчитанные Id–Vg, четыре Id–Vd и Cgg–Vg-кривые для planar MOSFET, FD-SOI, FinFET и GAA; кривые попадают в общий список и селектор графиков.
- Для мемристора и мемтранзистора эта кнопка становится **Сгенерировать характеристики памяти**: добавляет rate-dependent I–V и R–time петли мемристора либо гистерезисные Id–Vg sweep-кривые мемтранзистора. Параметры активного слоя, ионной подвижности, LRS/HRS и времени релаксации задаются в форме устройства; кривые доступны в общем списке и селекторе.
- Для мемристора в форме доступен выбор метода Verilog-A: существующая drift-модель и пороговая модель металлоксидного переключения для золь-гель активного слоя. Последняя описывает долю проводящего кислородно-вакансионного пути, SET/RESET пороги и геометрические параметры слоя, используя консервативный синтаксис для старых версий Virtuoso/Spectre; её параметры остаются поведенческими и требуют калибровки под конкретный оксид и измерения.
- Отдельная вкладка **Нейросетевые суррогаты** содержит режимы генерации тестовых данных, обучения и инференса для трёх U-Net: электростатический потенциал (Poisson), магнитостатический потенциал `Az` и упрощённые равновесные концентрации электронов/дырок. Checkpoint каждой сети независим. Автоматически создаваемые примеры предназначены только для проверки конвейера и не являются TCAD/измерениями; нейросети не заменяют основные физические решатели без обучения на проверенном датасете.
- Нейросети используют PyTorch CUDA, если доступно; AMP FP16, TF32, cuDNN benchmark, channels-last и pinned batches включаются только на CUDA, CPU остаётся резервным путём. DLSS — технология реконструкции изображения и напрямую не применима к физическим величинам; U-Net здесь выполняет научную реконструкцию поля, но не использует DLSS SDK. Установка `onnx` позволяет экспортировать обученный checkpoint для обмена, а расчёт приложения выполняется в PyTorch.
- Аппроксимация Id–Vg MOS-структур методом `scipy.optimize.least_squares` для оценки `VTH0`, `U0` и `NFACTOR`; для FinFET/GAA учитывается эффективный периметр канала.
- Для TFET/HEMT расчёт метрик непосредственно по кривой: порог по постоянному току, `ION`, `IOFF`, `ION/IOFF`, подпороговый наклон и максимальная крутизна `gm`. Для HEMT также оцениваются sheet resistance и сопротивление доступа.
- Для Id–Vd оцениваются максимальный ток, `RON`, выходная проводимость `gds` и gate bias, если он задан.
- Оценка `CGG`, `CGSO` и `CGDO` по C–V данным с использованием введённых размеров прибора.
- Интерактивная 3D-схема транзистора с редактируемыми размерами структур, автоматическим вращением и импортом STL-геометрии из CAD.
- Наложение расчётного поля цветом на поверхность структуры и показ координат/значения поля при наведении.
- Расчёт стационарного температурного поля методом конечных элементов (линейные тетраэдры) с оценкой `Tmax`, `ΔT` и `Rth`.
- Квазистатический 3D FEM-расчёт уравнения Лапласа для потенциала source/drain/gate с картой `|E|`. Отдельная карта магнитного поля оценивается аналитически по Biot–Savart.
- Кнопка **Рассчитать заряд носителей** решает самосогласованную нелинейную Poisson-задачу в 2D `x-z` или 3D `x-y-z`, включая эффективномассовые Schrödinger-подзоны по направлению конфайнмента. Рассчитанная концентрация отображается цветным сечением в 2D и тремя ортогональными сечениями в 3D; наведение показывает значение в ближайшей расчётной ячейке. Для FinFET/GAA учитываются дополнительные граничные поверхности затвора.
- Локально сгущаемая структурированная тетраэдральная FEM-сетка с уточнением около канала, затвора и границ слоёв.
- Решение разреженной FEM-системы в FP64 на CUDA через PyTorch sparse conjugate gradient, если доступно достаточно VRAM; иначе используется CPU solver SciPy. Backend и причины перехода на CPU показываются рядом с результатами. Размер сетки можно менять.
- Экспорт BSIM4 `.model` только для planar bulk MOSFET; для остальных структур экспортируется JSON-отчёт с параметрами и результатами, без заявления о совместимости с конкретной compact-моделью.
- Сохранение графиков в PNG/PDF.
- Отображение сведений GPU, если доступна команда `nvidia-smi`.

Моделирование на вкладке **3D / Тепло / Поле** собирает объёмную сетку из линейных тетраэдров; узлы сгущаются вблизи геометрически заданных канала, затвора и границ слоёв. Это адаптация распределения узлов по геометрии, а не итерационное уточнение по оценке ошибки решения. Тепловая модель использует один коэффициент `k`, источник `Vds * Id` и фиксированную температуру на внешних гранях. Электрическая модель использует постоянную диэлектрическую проницаемость, граничные потенциалы source/drain/gate и не учитывает подвижный заряд. Магнитное поле — отдельная аналитическая оценка Biot–Savart для конечного прямого проводника, не FEM-решение уравнений Максвелла. Это упрощённые инженерные оценки, а не полная Maxwell/TCAD-модель; слои разных материалов, контактные сопротивления, электромиграция, временные эффекты и самосогласованная электрика-тепло не учитываются.

Кнопка **Получить характеристики (PDE)** по-прежнему использует отдельный reduced-order 1D Poisson + gradual-channel расчёт для генерации Id–Vg, Id–Vd и Cgg–Vg. Кнопка **Рассчитать заряд носителей** выполняет самосогласованный 2D/3D Poisson-решатель с поперечными эффективномассовыми Schrödinger-подзонами, Fermi-Dirac заселением и Robin-условиями затвора; поле `cm^-3` отображает рассчитанную концентрацию электронов. 3D задаёт x-y-z конечную-разностную сетку, а для FinFET/GAA добавляются боковые/нижние границы затвора. UI рисует цветные сечения поля, чтобы избежать нестабильного 3D voxel-рендеринга Matplotlib. CUDA FP64 используется через PyTorch, если доступна и хватает памяти; иначе UI явно показывает CPU backend. Это квазистационарная reduced-order модель, не промышленный TCAD: она не решает неравновесные уравнения непрерывности carrier drift-diffusion, не учитывает impact ionization, рекомбинацию, многозонность, зависимые от поля/температуры параметры или неоднородные материалы. Конфайнмент — эффективномассовое приближение с прямоугольными границами; CAD-геометрия не используется как вычислительная сетка. Для проектных выводов нужны сеточная сходимость, калибровка и сравнение с измерениями или проверенным TCAD.

Характеристики мемристора/мемтранзистора генерируются отдельной CPU state-model, а не PDE-решателем: мемристор использует windowed linear ion-drift (Biolek) state model, мемтранзистор — феноменологическую релаксацию состояния и сдвиг порога. Эти данные демонстрационные и не являются калиброванной моделью конкретного материала или полноценным TCAD-расчётом.

Данные и CAD-образцы мемристора и мемтранзистора расположены в `data/examples/memory/`: CSV содержат полные sweep-точки и переменные состояния, JSON — параметры модели, ASCII STL — схемы слоёв. Каталог загружается кнопкой **Загрузить примеры** вместе с остальными curve-образцами. Для подбора согласованных параметров/геометрии откройте STL на вкладке 3D и загрузите парный JSON в диалоге импорта. Подробности и метрики приведены в `data/examples/memory/README.md`.

FEM-поля накладываются цветом на поверхность выбранной структуры; наведение курсора показывает координаты и интерполированное значение. Для CAD-геометрии существующее поле переносится на STL-поверхность по нормированным габаритам. Сам STL пока не задаёт объёмную сетку и не участвует в сборке FEM-матрицы. FEM electrical-field режим остаётся линейной задачей Лапласа; carrier-density режим — отдельный self-consistent quantum Poisson расчёт. Ни один из них не является полной промышленной drift-diffusion TCAD-моделью.

На NVIDIA GeForce RTX 4070 Ti SUPER (обычно 16 ГБ VRAM) и RTX 4090 (обычно 24 ГБ VRAM) новый quantum-Poisson и существующий FEM CUDA-путь используют FP64, если установлена CUDA-сборка PyTorch. Размер задачи ограничивается фактически доступной VRAM; при недостатке памяти расчёт выполняется на CPU, а backend указывается в результатах. Доступность GPU не подтверждает физическую точность: нужны проверка сеточной сходимости, калиброванные материалы/граничные условия и сравнение с измерениями или проверенным TCAD.

Для импорта чертежа экспортируйте его из AutoCAD или КОМПАС-3D в STL, нажмите **Загрузить CAD STL** на вкладке 3D и укажите единицы исходного STL (по умолчанию мм). Затем можно загрузить JSON-отчёт параметров, ранее экспортированный приложением, либо заполнить параметры в форме вручную. Импортированная структура появляется в списке типов как **CAD-транзистор**; CSV-анализ и расчёт поля используют выбранное семейство и параметры модели. Поддерживаются бинарный и текстовый STL; прямые DWG/STEP-файлы не читаются. FEM решается на текущей параметрической области, а не на импортированной CAD-геометрии.

Экстракция параметров также использует аналитическую компактную зависимость или измеряемые curve metrics. Геометрические поправки и квантово-полевой расчёт для FinFET/GAA являются reduced-order приближениями; TFET/HEMT не поддержаны quantum-Poisson решателем. Значения C–V являются упрощённой оценкой общей ёмкости и симметричных перекрывающих ёмкостей. DEVSIM, полный drift-diffusion TCAD и калибровка модели для каждого семейства не реализованы.

## Установка и запуск

Для чистой Python-среды требуется Python 3.10 или новее:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m src.main
```

Для Miniconda создайте отдельное изолированное окружение из `environment.yml`:

```powershell
conda --no-plugins env create --solver classic -f environment.yml
conda activate tspice-laboratory-e2e
python -m src.main
```

Файл создаёт чистое Conda-окружение Python и устанавливает все Python wheels из `requirements.txt` через pip, не смешивая Qt/CUDA DLL между каналами Conda и pip. `--no-plugins --solver classic` предотвращает запрос принятия ToS для неиспользуемых каналов `defaults` из глобальной конфигурации Conda; сам файл окружения использует только conda-forge. Не устанавливайте разные сборки PyTorch в одно и то же окружение. Запускайте приложение и тесты из активированного `.venv`/Conda-окружения; в IDE выберите тот же интерпретатор (`.venv\Scripts\python.exe` или `%USERPROFILE%\miniconda3\envs\tspice-laboratory-e2e\python.exe`). Статус GPU показывает путь активного Python и версию PyTorch.

Для разработки и запуска тестов:

```powershell
python -m unittest discover -s tests -v
```

Нейросетевой экспериментальный конвейер можно запускать отдельно от GUI. Команды создают три набора синтетических примеров, обучают одну или все три сети и выполняют отдельный инференс:

```powershell
python -m src.train_and_export_pinn examples --directory data/neural_examples --count 3
python -m src.train_and_export_pinn train poisson --samples 128 --epochs 30 --device auto
python -m src.train_and_export_pinn train all --samples 128 --epochs 30 --device auto
python -m src.train_and_export_pinn infer poisson --checkpoint data/neural_models/poisson.pt
python -m src.train_and_export_pinn export-onnx poisson --checkpoint data/neural_models/poisson.pt --output data/neural_models/poisson.onnx
```

Физические цели обучающих примеров упрощены и нормированы для теста конвейера: Poisson использует конечные разности с переменной диэлектрической проницаемостью, `Az` — скалярное Poisson-приближение магнитостатической задачи, а носители — локальное приближение равновесия и закон действующих масс. Для инженерного использования нужны собственные согласованные входы/метки от верифицированного решателя, контроль единиц, граничных условий и ошибок; тренировочная MSE сама по себе не подтверждает физическую точность.

Для чистой Python-среды все зависимости, включая CUDA-сборку PyTorch, устанавливаются одной командой из `requirements.txt`:

```powershell
python -m pip install -r requirements.txt
```

Манифест фиксирует Windows-совместимую версию `torch==2.7.1+cu128` с официального индекса PyTorch CUDA 12.8. Отдельного официального пакета `torch-gpu` нет: CUDA-сборка распространяется как пакет `torch`. Для RTX 4070 Ti SUPER или RTX 4090 необходим совместимый драйвер NVIDIA. После установки перезапустите приложение и проверьте статус **CUDA-решатель готов**. GPU-путь решения заряда использует FP64 матрично-свободный conjugate gradient; при недоступной CUDA или нехватке VRAM задача выполняется на CPU, фактический backend указан в результатах. Команды для других платформ и версий CUDA доступны на [официальной странице PyTorch](https://pytorch.org/get-started/locally/).

## Формат CSV

Файл CSV/текстовый `.log` должен содержать заголовок; поддерживаются запятая, точка с запятой, табуляция и разделение колонок пробелами. Значения должны быть в согласованных единицах: напряжение — В, ток — А, ёмкость — Ф, время — с, частота — Гц; AC gain передавайте как линейный модуль или столбец `H21_dB`/`U_dB`. Заголовки столбцов задают тип кривой:

| Кривая | Требуемые заголовки (примеры) | Расчётные метрики |
|---|---|---|
| Id–Vg | `Vg, Id` и необязательный `Vd` | `VTH0`, `U0`, `NFACTOR`, `ION/IOFF`, `SS`, `gm`, порог по постоянному току |
| Id–Vd / breakdown | `Vd, Id` (необязательно фиксированный `Vg`) | `RON`, `gds`, `IDS_MAX`, оценка напряжения излома `VBR_KNEE_V` |
| Ig–Vg | `Vg, Ig` | максимальная и минимальная ненулевая утечка затвора, их отношение |
| C–V | `Vg, Cgg`/`Cg`; необязательно `Cgs, Cgd, Cgb` | измеряемая `Cgg`-оценка, геометрическая оценка и средние дополнительные ёмкости |
| Gummel / BJT output | `Vbe, Ic, Ib` или `Vce, Ic` | `beta`, максимальные токи и выходная проводимость |
| AC | `Frequency, H21` и/или `U`/`Mason_U`, а также `S11..S22`, `Y11..Y22`, `Z11..Z22` | частота пересечения единичного усиления `fT`/`fmax` при наличии соответствующих кривых и максимумы переданных параметров |
| Transient / gate charge | `time, Vg, Id` либо `time, Ig` | времена нарастания/спада 10–90%, интеграл `Qg = ∫Ig dt` |

Метрики извлекаются из импортированных таблиц, а не генерируются полноценным ATLAS/Atlas3D решателем. `VBR_KNEE_V` — оценка излома по максимальному наклону log-тока, не сертифицированное напряжение пробоя; `fT/fmax` считаются только при наличии соответствующих gain-кривых. Нативные бинарные Silvaco `.str`, пространственные карты носителей, ударной ионизации и связанный drift-diffusion/self-heating расчёт пока не поддерживаются.

Экстракторы в `src/extractors.py` подбирают параметры transfer/C–V наборов методом `scipy.optimize.least_squares` и создают модельный текст. `VTH0` определяется линейной экстраполяцией в точке максимального `gm`; `U0`, `TOX/EOT` и `VFB` являются оценками на основе введённой геометрии и предоставленных кривых. LEVEL=54 для FD-SOI оставлен как запрошенная совместимость, но не заменяет BSIM-SOI/IMG и не моделирует back-gate физически. Для HEMT/TFET/CAD формируется полиномиальная поведенческая `.subckt`, а не ASM-HEMT/MVSG или BTBT-физика. Модели LEVEL=72 и поведенческие источники доступны только если поддерживаются конкретной версией симулятора; экспорт требует проверки в целевом SPICE и не гарантирует идентичную поддержку Tanner T-Spice, ngspice и Xyce.

Backend можно вызывать напрямую: `create_extractor(device, transistor_type).extract(v_graphs, c_graphs, id_graphs)`. `v_graphs` — словарь имён sweep → массив `Vg`; `id_graphs` — словарь sweep → `{ "vg": [...], "id": [...], "vd": float }` (ключи `linear`/`linear_0`, `saturation`/`saturation_0`); `c_graphs` — `{ "vg": [...], "cgg": [...] }`. Метод возвращает текстовую `.model`/`.subckt` карту, а метрики и ограничения доступны как `extractor.metrics` и `extractor.model_notes`.

Учебные CSV-примеры Id–Vg для всех семи семейств, а также Id–Vd и C–V находятся в [`data/examples`](data/examples/README.md). Образцы синтетические, но подходят для проверки интерфейса, экстрактора и экспорта.

```csv
Vg (V),Vd (V),Id (A)
0.0,0.05,1e-12
0.2,0.05,2e-10
0.4,0.05,1e-8
```

Для Id–Vg требуются столбцы `Vg` и `Id`; `Vd` задаётся отдельно для каждой точки или принимается равным 0.05 В. Для Id–Vd используются `Vd` и `Id`; при наличии постоянного столбца `Vg` он записывается как gate bias. Для C–V используйте `Vg` и `Cg` (допускается заголовок `capacitance`). Для экстракции нужно не менее пяти точек Id–Vg и трёх точек Id–Vd/C–V.
